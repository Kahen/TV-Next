# Native embedded/HLS subtitle selection (P4 partial)

Parent #5; implementation subtask #55. The original FongMi/TV subtitle settings UI (pinned source `123cc086159b0f13bf54bdf64bacbc259ca47c88`, `app/src/main/java/com/fongmi/android/tv/ui/dialog/SubtitleSettingPanel.java`) uses Android Media3 track selection. TV-Next implements only the corresponding **native Apple AVFoundation** media-selection subset; it does not port Media3, Android styling, dual subtitles, custom fonts or karaoke rendering.

The SwiftUI player exposes up to 16 `AVMediaSelectionGroup` options for the `.legible` characteristic on the installed `AVPlayerItem`. Selecting an option asks AVFoundation to render the embedded/HLS subtitle track. An explicit **off** option is shown only when `allowsEmptySelection` is true. Unsupported containers, codec-specific subtitles and media without a legible group continue playback without this menu. Existing imported SRT/VTT/ASS-text overlays remain separate and can coexist; the app does not promise to suppress duplicate overlays automatically.

Explicit subtitle selections (including **Off**, only when supported by the current media group) are saved locally for up to 100 titles in a 64 KB versioned UserDefaults snapshot. Keys are SHA-256 digests of the exact validated media URL; raw URLs, headers, local-file paths, replay sessions and numeric track indices are never persisted or synced. A new AVPlayerItem restores a subtitle track only on a **unique exact, untruncated display-name/language match** across the full AVFoundation option group, and only if the unique match is among the first 16 visible options. Display names longer than 80 characters remain visible as shortened menu labels but are **not persisted**, preventing two different renditions sharing the first 80 characters from being mistaken for each other. Missing, ambiguous, corrupted or unsupported choices leave the system selection untouched. An explicit Off is restored only if the new group permits empty selection. Switching items/retry cancels stale discovery; clearing the library deletes subtitle and audio preferences. The digest is not encryption and a shared device may still expose preference metadata. Switching tracks does not replace the player item or reset playback progress.

## Synthetic automated verification

The iPhone/iPad simulator workflow serves a local FFmpeg-generated 4-second HLS fixture with two synthetic AAC renditions and a synthetic WebVTT subtitle rendition declared through `EXT-X-MEDIA:TYPE=SUBTITLES`. XCTest checks discovery, valid selection, explicit off, invalid indices, stale-item rejection and reset on local-file switch and clear. Additional XCTest covers same-title track/off restoration after store recreation, corrupted and unmatched preference fallback, no raw URL persistence, local-file isolation and clear-data deletion. The full cross-platform gate must pass on the PR's final HEAD before merge.

No authorized external streams, physical-device codecs, VoiceOver, PiP/AirPlay subtitle rendering, native styled ASS/SSA or independent security review are claimed. Physical checks stay in #38. No signed IPA/Release is produced.

## Stale subtitle preference eviction (#150)

An explicit selection of an embedded/HLS subtitle track with a name longer than 80 characters, an empty name, or a language tag longer than 64 characters cannot be stored as a complete identity. Previously the app left the prior per-title preference in place, risking a stale rendition being restored on the next playback. The selection now keeps the current AVPlayer track but writes a bounded snapshot **without** the old entry. A valid track and explicit supported Off still persist normally. This uses only a SHA-256 media URL digest, never the URL or request headers.

Pure Swift positive/negative/80-81/64-65 boundary smoke and owned HLS XCTest verify the policy and actual store eviction. Both iPhone/iPad simulator acceptance and full integration are required on the final PR HEAD; this does not establish physical Apple-device codec/provider compatibility, independent audit or signed distribution.

## Hidden option identity collision regression (#152)

The native menu remains capped at 16 selectable entries, but matching a saved subtitle identity against only those 16 could incorrectly select a visible rendition if an otherwise identical 17th or later AVFoundation option existed. Restore now checks the **entire** reported group for uniqueness and permits only a uniquely matched index below 16. Missing, duplicated or out-of-menu matches preserve AVFoundation's current choice. Explicit Off and local persistence semantics are unchanged. The Foundation-only Swift smoke and iPhone/iPad XCTest cover unique 16th, hidden-only 17th, duplicate 17th, exact-language and malformed identity cases; the existing owned HLS fixture still exercises the production selection path. Final-head CI is required before merging. Real providers and physical hardware are not verified.
