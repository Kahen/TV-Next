# P2 cross-provider search (bounded Web + native iOS implementation)

This increment implements the subscription **跨站搜索** action on Web and native iPhone/iPad without introducing remote plugin execution. Search applies only to non-hidden, searchable type 0/1/2/4 HTTP providers from the user's loaded subscription. Type 3 Spider sites are deliberately excluded.

- At most **16 unique sites**, **4 concurrent requests**, **2 pages per site**, **40 items per page**, and **600 displayed results**. Each request uses the existing 20-second client timeout and server-side network restrictions.
- Web aborts pending requests on cancel, subscription reload, session-token change, or unmount. Native iOS cancels the structured search task on cancel, server/session changes and view disappearance; stale results are discarded via a request-generation check.
- Results appear in the subscription's site order, then page order, regardless of network completion order. Duplicate video IDs are suppressed **within** a site but preserved across different sites (IDs are provider-scoped).
- A failed provider does not discard successful results; its display name is reported without upstream exception contents or tokens. Explicit warnings report site/page/result truncation.
- Clicking a result requests detail from its original site. When the result belongs to a different site, native browsing resets the prior site's category, draft/applied filters and filter definitions before further navigation; same-site details preserve those choices. No arbitrary Spider/JavaScript execution occurs in either client.

Automated tests cover concurrent scheduling, duplicate handling, pagination, cancellation, partial failures, result caps and excluded sites on Web, plus native Swift concurrency/boundary smoke tests in the macOS iPhone/iPad CI matrix. Native results retain their original site key for detail and episode playback. The native helper receives only supported/searchable/visible sites; it does not execute Spider. **Not exhaustive:** deeper pages and sites past the cap are omitted with warnings. This is code-level native parity, not native UI automation or licensed-provider validation. Real permitted provider samples, server quotas and physical playback acceptance remain outstanding under Issue #3 and docs/ACCEPTANCE.md.
