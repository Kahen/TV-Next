# Native overlapping text captions

The native inline and fullscreen subtitle overlay shows up to four simultaneously active SRT/WebVTT/ASS/SSA text cues in parsed timeline order, separated by newlines. The combined display is capped at 2,000 characters. Previously only the first active cue was displayed, dropping a second language or another overlapping dialogue. The existing -10 to +10 second subtitle offset applies to the entire active set. Start is inclusive and end exclusive; one ending cue does not erase another still-active cue.

The [WebVTT specification](https://www.w3.org/TR/webvtt1/#webvtt-cue-timings) permits overlapping cues. This native text implementation does not reproduce WebVTT region/position layout or ASS layers, style positioning, fonts, animation or karaoke. More than four active cues and content beyond the combined display cap are deliberately omitted to bound the overlay. Parsing remains limited to 1 MiB, 5,000 cues and 2,000 characters per cue; markup is not executed. This applies to local and subscription external text captions through their existing shared overlay. Embedded/HLS AVPlayer track rendering remains system-controlled, and external overlays are not burned into PiP.

Swift smoke and native XCTest cover actual parsed overlapping WebVTT, SRT and ASS, double-language output, comma/line-break content, inclusive/exclusive boundaries, positive/negative offsets, nonfinite inputs and crowded/long display limits. Existing production player/fullscreen/lifecycle UI acceptance must pass on both iPhone/iPad in the final-head full gate. Physical subtitle layout/readability remains #5/#38.
