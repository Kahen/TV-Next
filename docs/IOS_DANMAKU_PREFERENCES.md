# Native iOS danmaku presentation preferences

P4 implementation slice: [Issue #94](https://github.com/Kahen/TV-Next/issues/94). The SwiftUI danmaku controls now restore their last locally saved values on iPhone/iPad app relaunch. The existing native overlay still uses the same parser, timeline and renderer; this change does not implement a new danmaku source or protocol.

Original-source mapping: FongMi/TV commit `e3e81c27ec54d29689f4ef28cdeb9922f8fbc718`, `app/src/main/java/com/fongmi/android/tv/setting/DanmakuSetting.java`, persists presentation/timing values through `Prefers` with bounded getters (for example show, text scale, transparency, duration and offset). The iOS snapshot preserves that local-preference behavior for the **already implemented** SwiftUI controls, not the original Android-specific font/style/density/API features. Source: https://github.com/FongMi/TV/blob/e3e81c27ec54d29689f4ef28cdeb9922f8fbc718/app/src/main/java/com/fongmi/android/tv/setting/DanmakuSetting.java

The versioned UserDefaults key stores only enabled, opacity, font size, display area, display duration, timeline offset and comma-separated blocked words. Media URLs, subtitle/danmaku content, authentication headers, subscription addresses and account credentials are never included in this snapshot. It is device-local and is not part of the home-server library sync.

Loading rejects malformed, incomplete, oversized (over 8 KiB), non-finite and out-of-range snapshots and uses safe defaults. Saving rejects invalid values without overwriting the last good snapshot. The blocked-word field is limited to 4 KiB UTF-8, and the SwiftUI input truncates on Unicode scalar boundaries rather than saving a partially encoded character. Defaults are enabled, 0.8 opacity, 22-point font, half-screen area, eight-second display, zero offset and no blocked words.

Validation: Linux-compatible Swift smoke runs positive, malformed, non-finite and size-bound cases; XCTest additionally checks all fields, corrupted payloads, isolated stores and clearing. Final-head Xcode iPhone/iPad simulator XCTest/XCUI and the complete integration gate must pass before merging. Physical-device display, external providers, native signing and formal release remain unverified.

CI regression (2026-10-30): the first full gate failed on both iPhone and iPad because the XCUI test assumed that a SwiftUI switch exposes its value as the literal string `"0"` or `"1"`. The production screen now includes an accessible, user-visible enabled/disabled status, and the relaunch test asserts that semantic state while still tapping the real switch. This does **not** waive a failed UI assertion: final-head iPhone/iPad and full integration must pass before merge.
