# Native iPhone/iPad audio track selection (P4 partial)

The SwiftUI player exposes a **per-item** audio-track menu when AVFoundation reports an `AVMediaSelectionGroup` for the audible characteristic. Labels are bounded and numbered to distinguish duplicate languages. The selected option is applied directly to the current `AVPlayerItem` without replacing the item or losing playback progress.

The list is limited to the first 16 options. Unsupported codecs, containers with no selectable group, external audio files, system-managed routes and DRM-specific track handling are **not** made compatible by this menu. A missing menu means AVFoundation did not expose selectable audio tracks; it does not mean the source has no audio. An explicit audio selection is saved locally for up to 100 titles using a SHA-256 digest of the exact media URL (not the raw URL). Only a unique exact display-name + language-tag match is restored when AVFoundation discovers a new item's audio group. An absent or ambiguous match leaves the system default; no stale track index is reused. Preferences are never synced or sent to the server, and clearing the library deletes them. URLs that rotate query tokens count as different titles. The stored track label is untrusted metadata, not an encrypted secret. New playback items and retries invalidate old track handles and asynchronous discovery results.

## Automated acceptance

The iOS CI creates a source-free 4-second HLS master playlist with two alternate synthetic sine-wave AAC renditions using FFmpeg, served from a loopback-only HTTP fixture. The master declares two `EXT-X-MEDIA:TYPE=AUDIO` options so AVFoundation can expose a media-selection group. `MediaLibraryTests.testAudioTrackSelectionIsItemScopedAndRejectsInvalidIndices` covers discovery, selection, negative/out-of-range indices, switching items and clearing the library. Additional XCTest covers explicit selection persistence, same-title restoration after store recreation, invalid indices, corrupt saved data, local-file isolation and deletion. The same workflow builds the production SwiftUI app and runs XCTest/XCUI on iPhone/iPad simulators.

These checks do **not** establish physical Apple codec compatibility, audio quality, energy use, AirPlay route behavior or accessibility validation with VoiceOver. Record those separately in #38. No signed IPA/Release is produced.
