# Native iPhone/iPad audio track selection (P4 partial)

The SwiftUI player exposes a **per-item** audio-track menu when AVFoundation reports an `AVMediaSelectionGroup` for the audible characteristic. Labels are bounded and numbered to distinguish duplicate languages. The selected option is applied directly to the current `AVPlayerItem` without replacing the item or losing playback progress.

The list is limited to the first 16 options. Unsupported codecs, containers with no selectable group, external audio files, system-managed routes and DRM-specific track handling are **not** made compatible by this menu. A missing menu means AVFoundation did not expose selectable audio tracks; it does not mean the source has no audio. An explicit audio selection is saved locally for up to 100 titles using a SHA-256 digest of the exact media URL (not the raw URL). Only a unique exact **full, untruncated** display-name + language-tag match is restored when AVFoundation discovers a new item's audio group. Menu labels can be shortened to 80 characters, but names longer than 80 characters are **not persisted**: two distinct tracks sharing the same prefix must never be confused. Choosing such an unpersistable track clears any older preference for that title. The version-2 snapshot stores full identities; legacy version-1 entries exactly 80 characters long are discarded during migration because they may have been truncated. Shorter legacy names remain eligible for exact matching. This may reset a legitimate old 80-character choice, favoring correctness over a potentially wrong automatic selection. An absent or ambiguous match leaves the system default; no stale track index is reused. Preferences are never synced or sent to the server, and clearing the library deletes them. URLs that rotate query tokens count as different titles. The stored track label is untrusted metadata, not an encrypted secret. New playback items and retries invalidate old track handles and asynchronous discovery results.

## FongMi reference and native scope

The pinned upstream [FongMi/TV `123cc086` TrackDialog](https://github.com/FongMi/TV/blob/123cc086159b0f13bf54bdf64bacbc259ca47c88/app/src/main/java/com/fongmi/android/tv/ui/dialog/TrackDialog.java) passes a selected track to [PlayerManager.setTrack](https://github.com/FongMi/TV/blob/123cc086159b0f13bf54bdf64bacbc259ca47c88/app/src/main/java/com/fongmi/android/tv/player/PlayerManager.java); [TrackUtil](https://github.com/FongMi/TV/blob/123cc086159b0f13bf54bdf64bacbc259ca47c88/app/src/main/java/com/fongmi/android/tv/player/track/TrackUtil.java) manages Android Media3 selection parameters. TV-Next preserves the user-visible track-choice intent, but uses AVFoundation media-selection options and an independent local identity. Android track keys/decoder overrides are **not** portable to iOS.

## Automated acceptance

The iOS CI creates a source-free 4-second HLS master playlist with two alternate synthetic sine-wave AAC renditions using FFmpeg, served from a loopback-only HTTP fixture. The master declares two `EXT-X-MEDIA:TYPE=AUDIO` options so AVFoundation can expose a media-selection group. `MediaLibraryTests.testAudioTrackSelectionIsItemScopedAndRejectsInvalidIndices` covers discovery, selection, negative/out-of-range indices, switching items and clearing the library. Additional XCTest covers explicit selection persistence, same-title restoration after store recreation, invalid indices, corrupt saved data, local-file isolation and deletion. The full-name regression tests cover two 80-character-prefix collisions, legacy truncated values, exact name/language matches, missing language and duplicate names. These are identity-level synthetic checks, not evidence of real-provider audio compatibility. The same workflow builds the production SwiftUI app and runs XCTest/XCUI on iPhone/iPad simulators.

These checks do **not** establish physical Apple codec compatibility, audio quality, energy use, AirPlay route behavior or accessibility validation with VoiceOver. Record those separately in #38. No signed IPA/Release is produced.

## Hidden option identity collision regression (#152)

A saved exact audio identity is now checked against **all** options in the AVFoundation audible group, rather than only the first 16 displayed choices. A matching 17th-or-later option is not selectable, and a later duplicate invalidates an otherwise visible match. The first-16 UI cap, current default selection on ambiguity, exact identity, digest-only persistence and per-item cancellation remain unchanged. Foundation-only Swift smoke, native XCTest and final-head iPhone/iPad simulator plus complete integration CI provide code evidence; physical codec/provider compatibility remains open.
